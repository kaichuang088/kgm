### 查到並修掉的
1. **兩份航段清單**（反覆出現的 bug 型態 1）：「無機可派」的量測自己用 `FLIGHTS`＋`flyOn` 算一份，排班引擎用 `dayOf72` 算另一份（包含後台新增航班、季節時刻 `seasonSchedulesR48`、同一天同班號去重、排除 codeshare）。乾淨的狀態兩份完全相同（115088＝115088），但只要電腦上存了後台修改，兩份就可能對不起來 —— 量出「無機可派」其實是兩份清單的差，不是真的沒飛機（或反過來，真的沒排到的被漏算）。
   → 量測改用**排班引擎同一份清單**；時刻表有、排班清單沒有的另外列為「時刻表有、但沒有進入機隊排班」（不混在無機可派裡），兩個都會列出是哪幾段。
2. **台灣時區日期偏一天**：量測的日期函式用「本地午夜 → toISOString()」，在 UTC+8 會變成前一天，整個量測視窗往前偏一天（台北時區 expected 從 115088 變 114769）。→ 改成本地日期計算。修完後台北與 UTC 都是 115088。
3. **補位沒有調機選項**：原本的補位只接受「飛機剛好停在出發站」或「TPE 出發的去回成對」。外站出發、當下沒有飛機在那裡的航段永遠補不上。→ 第三輪：找一架同級或更大的機身（窄體／廣體不互換），空檔夠就插入調機（無乘客定位航段，格式與 r72 的 positioningR830 相同）。
   實測：新增一班 11-17 NRT→TPE 23:40（外站沒有飛機）→ 原本無機可派 1 → 第三輪由 B-58113 補上：TPE→NRT 調機 18:16–22:40，接 KX997 23:40，無機可派 0。
4. **機隊頁只看得到一個數字**：現在「輪轉檢查」下面會列出每一段（日期、班號、航線、機型），並有「下載排班診斷檔」按鈕（含時區、量測結果、這台電腦上保存的航班／機隊修改；金鑰、密碼、訂位、會員資料不會放進去）。

### 為什麼沒有改機型、PDF 沒有換
[確定] 看起來 A339L 13/13、A339R 15/15、A21N 25/25、A35K 8/8 每天都全用上，但那是 1006A 起的 EQV 一年期派機**刻意把可互換的航班分給所有飛機**（例如 KX101 一年裡 210 天是 A21N、其他天是別的機型）。真的少了飛機（維修、退役）時，EQV 會把航班換給別的機型，上表每個情境都證明了這點。時刻表本身沒有運力不足，所以這一輪沒有改任何航班的機型；ZIP 裡的時刻表 PDF 內容與 1008A 相同（只改檔名版號）。

### 還不知道的
[確定] 使用者那台電腦上的 69 段仍然沒有重現。1008B 的修正把兩個已知可能原因（兩份清單、時區）消掉，並補上調機補位；如果開 1008B 還有缺口，機隊頁會直接列出是哪幾段，按「下載排班診斷檔」把檔案給我們就能重現。

## 二、後台 AI —— 不經 Worker 的辦法

之前回覆是固定模板，是因為網站連不上 Worker，才改用站內規則引擎。1008B 加了第二條路：

1. **直接連線（新）**：後台 AI 視窗上方按「連線」→ 貼上 Anthropic API 金鑰（console.anthropic.com → API Keys）→「測試」→「儲存」。
   之後後台這台電腦直接呼叫 Anthropic API（`api.anthropic.com/v1/messages`，Claude Opus 5.5，effort medium，`fallbacks: "default"`），不需要 Worker。
   - 金鑰只存在這台電腦的瀏覽器（localStorage `kgm_ai_key_r1008b`），**不會**寫進 `save()`、不會同步到前台、不會放進診斷檔。
   - 能使用這台電腦瀏覽器的人都讀得到金鑰 —— 建議在 Anthropic Console 為這把金鑰設每月用量上限。
   - 工具定義跟 Worker 同一份（建置時從 `worker_ai_1008B.txt` 取出），權限照舊由網站依職務檢查。
2. **Worker**：沒有設定金鑰時走 Worker 的 `/ai/admin`（跟以前一樣）。
3. **站內規則引擎**：兩條都不通才用；回覆下方寫出兩條路各自失敗的原因。
4. 每一則 AI 回覆下方會註明是哪一條路線回答的（例如「Claude · claude-opus-5-5 · 直接連線」）。

實測（Chromium，用檔案直接開網站，網址是 `file://`）：
- 用假的金鑰真的打 `api.anthropic.com`：回 HTTP 401「API key is invalid.」—— 代表瀏覽器跨網域（CORS）這條路是通的、請求有送到 Anthropic；
- 模擬 API 正常回應（思考區塊＋文字＋工具呼叫）：網站解析後執行工具（切到票價分析），註記「直接連線」；送出的請求帶了正確的 header、24 個工具（含 crew_trip_change 完整參數）、effort medium、fallbacks default；
- 模擬 401：退回站內規則引擎，原因寫「直連：API 金鑰無效；Worker：連不到 Worker…」。
- **沒有做到的**：沒有用真的金鑰跑過一次完整對話（這個環境沒有金鑰）。
